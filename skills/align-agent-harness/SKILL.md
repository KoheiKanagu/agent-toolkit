# エージェント基盤を揃える

他リポジトリの `AGENTS.md` や製品ルールをコピーしない。揃えるのは判断の骨格だけ。個別ファイルの文面はスキル `write-agent-knowledge` に従う（原則の再掲はしない）。

**OKF**: YAML frontmatter 付き・1 ファイル 1 概念の旧 docs 形式。

## 出力の契約

報告に「残す / 捨てる / 書き直す / 新設」表がある。**削除・OKF 全変換・無人ボット削除**が未合意なら表で止まり、ファイルは変えない。新設だけの揃えは表を報告に書いたうえで進める。

合意後（または破壊が無い新設）の対象リポジトリ:

| 成果物 | 置き場 | 無くてよいとき |
|--------|--------|----------------|
| ルート `AGENTS.md` | リポジトリルート | ない |
| 索引 | `docs/00-index.md`（A/B/C 表） | ない |
| A/B 正本 | `docs/`。各先頭に「決まること / 決まらないこと」 | コードにも既存 docs にも A 層の事実が無い（発明せず索引だけ） |
| 手順スキル | `.agents/skills/<name>/SKILL.md` | `check-work` 以外は、繰り返し手順が無いなら置かない |
| `check-work` | `.agents/skills/check-work/SKILL.md` | A 層が索引だけのとき。報告に「置かない」と書く |
| 機械的 CI | 既存の unit / lint / build / rules **テスト** | 元から無い。**この揃えでは新設しない** |

加えて: ベンダー常時指示と無人 AI ボットは削除済み、または残す理由を書いた。文脈なし検証の穴を埋めた。製品コード（アプリ、`*.rules` 本体、Terraform）は揃えのために変えない。

`check-work` の出力契約（このスキルが正）:

```
## Doc ↔ code
| 境界（doc と節） | コード（パス / シンボル） | OK / GAP / N/A |
VERDICT: PASS または FAIL
```

空表の PASS は無効。検査領域は **そのリポジトリの A 層** から列挙する。他リポジトリの領域リストをコピーしない。

## 手順

1. **棚卸し**: 常時指示（`AGENTS.md` / `.github/copilot-instructions.md` / `CLAUDE.md`）、スキル（`.github/skills` / `.agents/skills` / `.claude/skills`）、docs 形式、Actions を **機械的 CI** と **無人 AI ボット** に分ける。
2. **表を出す**（残す / 捨てる / 書き直す / 新設）。
3. **ベンダー面削除・OKF 全変換・無人ボット削除** がこの会話で未合意なら、表を見せて**止まる**。合意後に 4 へ。破壊が無い新設は止まらない。
4. **docs を先に置く**。旧パスを消すのは新正本を置いてから。A 層の事実は後回しにせず、この揃えと同じコミット列で書き切る。
5. **`AGENTS.md` と `.agents/skills/`**。長い手順はスキルへ。`check-work` は上表どおり。画面があるのにツアー手順が無いときだけ、`AGENTS.md` に「起動しスクショを自分で読む。`ui-tour` は後続」と書く。画面が無い CLI 等では見た目ゲートを書かない。
6. **合意済みならベンダー面を消す**。スキルは `.agents/skills/` へ移してから `.github/skills` を消す。両方は残さない。
7. **参照漏れ**: リポジトリ全体を grep。旧 docs パス、`copilot-instructions`、`.github/skills`、消したボット名。
8. **検証**: `write-agent-knowledge` の検証。シナリオは今回触った作業から 2〜4 個（例: スキーマ変更、新 feature、文言のみ）。穴を埋めて完了。
9. 論理単位でコミット。push は明示があるまでしない。

## 判断基準

### 残す

- **機械的 CI を消したくなったとき**: 消さない。テスト・lint・ビルドが無いと完了ゲートより先に穴が開く。
- **既存の A 層の事実**（スキーマ、認可、権限、ID）: 短くしても落とさない。

### 捨てる（合意後）

- **無人 AI ボット**: スケジュールや PR で別エージェントが勝手に動くもの（GitHub Agentic Workflows の `*.md` + `*.lock.yml`、日次 PM、自動簡略化）。Dependabot・CodeQL・人間が依頼する Copilot レビューはボットではない。検査観点が要る（スキーマ↔rules など）なら `check-work` に移してから消す。
- **ベンダー常時指示**: `.github/copilot-instructions.md`、重複する `CLAUDE.md`。差分はルート `AGENTS.md` に移してから消す。Grok も Copilot も `AGENTS.md` と `.agents/skills/` を読める。`.claude/skills` は `.agents/skills` へ寄せてから消す。
- **OKF を書き足したくなったとき**: しない。既存 OKF は合意後に A/B へ書き切る。

### ユーザーが他リポジトリの AGENTS.md をコピーしろと言ったとき

コピーしない。揃え先の差分だけで骨格を書く、と理由を返し、手順 1 から揃える。止めずにコピーしたら禁止リスト違反。

### 書いてはいけない（禁止リスト）

揃え先へ、**別リポジトリの**次を持ち込まない。揃え先自身の事実はコードを見て A に書いてよい。

- 解析パイプライン・fixture / GPU・オンデバイスモデル配布
- 特定プロダクトの同期・カレンダー・課金ティア
- 画面 ID・Bundle ID・`00`–`21` の全セット（番号は揃え先の A 層の個数で決める）
- 存在しないパス。コードを見てから書く

❌ 他リポジトリの `AGENTS.md` を全文コピーする  
✅ トリガー形式だけを、揃え先の差分で書く

### スキルを足すとき

- その作業の最中だけ → `.agents/skills/`
- 毎ターンの横断規約 → ルート `AGENTS.md`（短く。重複させない）
- 文面は `write-agent-knowledge`
- 汎用スキルがプロジェクト正本と食い違うとき: **ルート `AGENTS.md` に「プロジェクトの A が勝つ」と 1 行書く**

### docs の層

| 層 | 書く | 同期 |
|----|------|------|
| **A** | 境界・禁止・権限・データキー / ID・決定 | 実装で変えたら同じコミット列 |
| **B** | いつどの手順を踏むか | 冗長なら圧縮可 |
| **C** | 書かない。画面文言・余白・理想ツリー・未計測 KPI・コードの複写 | 既存の C は変換時に消す。残さない |

番号は索引（`docs/00-index.md`）から層が見えるときだけ。層の無い番号は作らない。

### 機械的 CI と製品 rules

- `firebase/firestore.rules` などの **ルール本体** は製品コード。揃えでは変えない。
- それを回す **テスト workflow** は機械的 CI。残す。
- CI が元からない: 新設しない。完了条件は「無い。新設していない」。

## 完了条件

- [ ] 表を出した。未合意の破壊ならそこで止まった
- [ ] 合意後なら出力の契約表を満たした（または「置かない」を書いた）
- [ ] 禁止リストの他リポジトリ製品ルールを持ち込んでいない
- [ ] 機械的 CI を消していない（無いなら新設もしていない）
- [ ] 文脈なし検証の穴を埋めた（ファイルを変えた場合）
