# 新しいプロジェクトのエージェント基盤

個人の開発方針はグローバル `AGENTS.md`（`agent-toolkit` → `~/.grok/AGENTS.md`）が正。プロジェクトにコピーしない。プロジェクト `AGENTS.md` には **そのリポジトリ固有の情報だけ** を書く。文面は `write-agent-knowledge`。

## 出力の契約

| 成果物 | 置き場 | 無くてよいとき |
|--------|--------|----------------|
| プロジェクト `AGENTS.md` | リポジトリルート | 固有の境界・正本・トリガーがまだ無い（グローバルだけにする。報告に書く） |
| 索引 | `docs/00-index.md`（A/B/C 表） | ない |
| A/B 正本 | `docs/`。各先頭に「決まること / 決まらないこと」 | コードにも既存 docs にも A 層の事実が無い（発明せず索引だけ） |
| `check-work` | `.agents/skills/check-work/SKILL.md` | A 層が索引だけのとき。報告に「置かない」 |
| 手順スキル | `.agents/skills/<name>/SKILL.md` | 繰り返し手順が無い |
| `.grok/lsp.json` | リポジトリの `.grok/lsp.json` | ユーザーが Language Server 不要と言った。報告に「置かない」 |

機械的 CI と製品コードはこのスキルでは新設も変更もしない。他リポジトリの `AGENTS.md` / スキル / 番号付き docs 一式はコピーしない（`grok/lsp/` から `.grok/lsp.json` へのコピーだけ例外）。文脈なし検証の穴を埋めた。

`check-work` の出力契約（本スキルが正）:

```
## Doc ↔ code
| 境界（doc と節） | コード（パス / シンボル） | OK / GAP / N/A |
VERDICT: PASS または FAIL
```

空表の PASS は無効。検査領域は **このリポジトリの A 層** から列挙する。

## 手順

1. **コードと既存 docs から固有情報を拾う**（ビルド手段、データ境界、認可、モジュール規約）。無い事実は書かない。
2. **グローバルに既にあるか見る**（`~/.grok/AGENTS.md`、`~/.grok/skills/`）。個人方針・横断スキルはプロジェクトに複製しない。
3. **`docs/00-index.md` を先に置く**。A 層の事実があれば同じコミット列で正本も置く。
4. **プロジェクト `AGENTS.md`**。固有のトリガーだけ。長い手順は `.agents/skills/`。
5. **Language Server**: 下の判断基準どおり。言語が揃ってから `grok/copy-lsp.sh` を実行する。依頼が Language Server だけのときは手順 3・4・6 の骨格は置かない。
6. **`check-work`** は上表どおり。画面があるのにツアーが無いときだけ「起動しスクショを読む。`ui-tour` は後続」とプロジェクト `AGENTS.md` に書く。画面が無いなら書かない。
7. **検証**: `write-agent-knowledge`。シナリオは今回置いた骨格から 2〜4（例: スキーマ変更、新 feature、文言のみ）。
8. 論理単位でコミット。push は明示があるまでしない。

## 判断基準

### どちらに書くか

- **個人の進め方・横断ポリシー**（コミット、push、sandbox、レビュー、フォローアップ）→ グローバル。プロジェクトに再掲しない。
- **このリポジトリだけの境界**（正本パス、認可キー、モジュールの切り方、完了ゲートの領域）→ プロジェクト `AGENTS.md` または A doc。
- **迷ったらグローバルに残す**。プロジェクトに書いたら、そのリポジトリでしか守れなくなる。

### 書いてはいけない

- 他リポジトリの製品ルール（解析パイプライン、fixture / GPU、特定の同期・課金・画面 ID）
- グローバル `AGENTS.md` の全文
- 存在しないパス。コードを見てから書く
- 新しい OKF concept（YAML frontmatter + 1 ファイル 1 概念）

❌ 他プロジェクトの `AGENTS.md` をコピーして名前だけ変える  
✅ このリポジトリの差分だけをトリガーで書く

### Language Server

- **骨格を置くとき、またはプロジェクトに Language Server を足すとき**: 依頼が `grok/lsp/` のファイル名（拡張子なし）を言語として含んでいればそれを使う。無ければユーザーに一覧を出して確認し、答えが来るまでスクリプトを走らせない。指定言語で `grok/copy-lsp.sh <対象リポジトリ> <lang> [lang ...]` を実行して完了とする。不要と言われたなら置かないと報告する。依頼が Language Server だけのときは docs / プロジェクト `AGENTS.md` / `check-work` は置かない。理由: Grok は設定に書いたサーバをセッション開始で全部起動する。
- **対象リポジトリ**: 依頼でパスや名前が出たリポジトリ。無ければ今開いているワークスペース。どちらも無ければユーザーに確認する。
- **スクリプトの場所**: `agent-toolkit/grok/copy-lsp.sh`。`~/.grok/skills/bootstrap-agent-harness` が symlink なら、リンク先ディレクトリから見て `../../grok/copy-lsp.sh`。symlink でない・パスが無いときはユーザーに確認し、コピーせず完了としない。
- **リポジトリの中身から言語を推測しない。**
- **`grok/lsp/<lang>.json` を直したとき**: 今開いているワークスペースに `grok/copy-lsp.sh <repo> <lang>` を実行して完了とする。他リポジトリは依頼で名前が出たものだけ。
- **`.grok/lsp.json` を手で書かない。** マージはスクリプトがやる。
- **`~/.grok/lsp.json` には書かない**（ユーザーがグローバルへ書けと言っても）。同じ言語を対象リポジトリへスクリプトで入れる。

❌ リポジトリの中身から言語を推測する / `~/.grok/lsp.json` に並べる / JSON を手でマージする  
✅ ユーザーが指定した言語で `grok/copy-lsp.sh` を実行する

### スキルを足すとき

- このリポジトリの作業中だけ → `.agents/skills/`
- 全プロジェクトで使う → `agent-toolkit`（このスキルの対象外。別依頼）
- 汎用スキルがこのプロジェクトの A と食い違うとき: プロジェクト `AGENTS.md` に「こちらの A が勝つ」と 1 行

### docs の層

| 層 | 書く | 同期 |
|----|------|------|
| **A** | 境界・禁止・権限・データキー / ID・決定 | 実装で変えたら同じコミット列 |
| **B** | いつどの手順を踏むか | 冗長なら圧縮可 |
| **C** | 書かない。画面文言・余白・理想ツリー・未計測 KPI・コードの複写 | — |

番号は索引から層が見えるときだけ。層の無い番号は作らない。`00`–`21` を「あるべきセット」として複製しない。

## 完了条件

- [ ] グローバル方針をプロジェクトに複製していない
- [ ] プロジェクト側は固有情報だけ（または「固有が無く置かない」と書いた）
- [ ] 他リポジトリの製品ルールを持ち込んでいない
- [ ] CI を新設していない
- [ ] 指定言語で `grok/copy-lsp.sh` を実行した（またはユーザーが不要と言い「置かない」と書いた）
- [ ] `~/.grok/lsp.json` に言語サーバを足していない
- [ ] 文脈なし検証の穴を埋めた
